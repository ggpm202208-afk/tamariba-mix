①Discord Botを作る

5分0 / 8

Botのアカウントを作り、トークンとApplication IDの2つを手元に控えます。この2つが以降すべての土台です。

!トークンはパスワードと同じです。GitHubに上げない、人に見せない。漏れたら Reset Token で即座に無効化できます。
!インテントは全部OFFで動きます。リアクションの取得に特権インテントは不要で、メッセージ本文も読みません。

②Botをサーバーに招待する

3分0 / 6

権限を指定したURLで招待します。ここで権限を間違えると、あとで「人数が0のまま」になります。

https://discord.com/oauth2/authorize?client_id=APP_ID&permissions=93248&scope=bot%20applications.commands

permissions=93248 の中身

権限用途
チャンネルを見る募集チャンネルの読み取り
メッセージを送信通知・振り分け結果の投稿
メッセージ履歴を読むリアクション取得に必須。無いと0人のまま
リアクションを追加募集メッセージに ✅🟡 を付ける
埋め込みリンク振り分け結果のカード表示
メッセージの管理前日の募集メッセージ削除（/reset 時）
!古い permissions=85056 のURLで招待済みなら、サーバー設定 → 連携サービス から一度 Kick し、上のURLで再招待してください。「リアクションを追加」が無いと 🟡 だけ付かず、募集が壊れます。
!チャンネルIDが表示されない場合は、Discord設定 → 詳細設定 → 開発者モード をON。
③

③スプレッドシートを準備する

5分0 / 5

既存のシートをそのまま使えます。Workerは「Discordの表示名」と「B列の名前」を照合し、C列のURLからExperienceを引きます。B列はmgo2pcのキャラ名である必要はありません。

https://docs.google.com/spreadsheets/d/【ここがID】/edit
!「制限付き」のままだとWorkerがシートを読めません。Experienceが全員0になり、振り分けが機能しません。
!照合するのは「Discordの表示名」と「B列」だけです。B列＝mgo2pcのキャラ名である必要はありません（C列のURLが繋いでくれます）。せお と SEO のように違っていても、B列が表示名と同じなら正しく引けます。
!B列と表示名が違う人は、Discordの表示名をそのまま mgo2pc のキャラ名として照合します。それも外れた場合だけ Experience 0 になり、振り分け時に ⚠️ プレイヤーDBに未登録 とDiscordに投稿されます。その人のURLを「プレイヤーを追加」に貼れば直ります。

⑤Workerを作る

10分0 / 6

配布した pipeline/worker.js をそのまま貼ります。編集は不要です。

!貼り付けが途中で切れると真っ白なエラーになります。先頭の const API = から最終行の const text = まで入っているか確認してください。
!編集中の右側プレビューはまだ公開されていないコードを動かしています。右上の Deploy を押すまで、外からURLを開いても繋がりません（DNS_PROBE_FINISHED_NXDOMAIN の原因）。
!Error 1101 が出たら、まずログではなくURLを疑ってください。最新版は例外を握って理由をJSONで返すので、1101は出ません。

⑥環境変数とKVを紐付ける

5分0 / 7

Workerの Settings → Variables and Secrets で順に追加します。変数名は1文字も変えないでください。

変数名値種類
DISCORD_BOT_TOKEN①のトークンSecret
CHANNEL_ID②のチャンネルIDText

CAP12Text

PHANTOM_KEYPhantomJSCloudのキー（任意）Secret
!KVのバインディング名が KV でないと差分通知が出ません。別名にすると無言で機能しなくなります。
!変数を追加しただけでは反映されません。最後に必ず Deploy を押してください。
!/debug は変数が入っているかを一覧で返します（値そのものは出ません）。/status が繋がらないときは先にこちらを開いてください。

⑧募集メッセージを作る

3分0 / 5

WorkerのURLに合言葉を付けて開くだけです。メッセージIDはKVに自動保存されるので、環境変数を書き換える必要はありません。

https://YOUR-WORKER.workers.dev/setup?key=合言葉
!forbidden が返るのは合言葉違いだけです。⑥の SETUP_KEY を確認してください。
!/setup は何度開いてもメッセージが増えません。生きている募集があれば reused: true で再利用します。作り直したいときは末尾に &force=1 を付けてください。
⑨

⑨動作確認

5分0 / 8

ここまで来たら、実際に押して確かめます。1つでも落ちたら、その項目の番号をトラブルシューティングで引いてください。

https://YOUR-WORKER.workers.dev/status
!9-3で止まる場合は ⑥の KV、9-4で止まる場合は ②の「メッセージ履歴を読む」を疑ってください。

全部チェックが付いたら、あとは毎日 /reset を開くだけ

前日の募集メッセージは自動で削除され、新しい募集が始まります。ブックマークに入れておくと1タップです。
